Learning: Stacks and Queues

Why Stacks and Queues?

Stacks and Queues are reletively similar in their implementation and how they operate. Because of their similarity, they are often taught togehter since understanding one can give insight into the other.

Abstract Data Type (ADT)

One of their similarities is that they are both Abstract Data Types (ADT). ADTs are a conceptual model which describes the behavior of the data type without a concrete outline of the implementation. As such, these focus on the 'what' (what the data type does) rather than the 'how' (how the data type does these things).

Why aren't Linked Lists or Array Lists ADTs? These things aren't ADTs because the underlying implementation details are clearly outlined. For Array Lists, we know that an array must be used to store the data. For our Linked List we know we must create a Node, with each Node linking to some other Node. Though the specifics of the implementation can change for different uses, the important implementation points are the same across the board.

What is a Stack?

You can think of a Stack like a stack of plates. With a stack of plates, you put the plate on the top of the stack. Then, when you are trying to grab a new plate, you also take from the top of the stack of plates. This is the same with Stacks in computer science. The last item added to the stack is the first item out of the stack (Last In First Out: LIFO).

Stacks are helpful in more complex aglorithms (Kosaraju’s Algorithm) or when computing mathematical equations with Reverse Polish Notation. In general, stacks are helpful when the most recent item added to the stack should be the item used next.

Remember, Stacks are ADTs and thus specific implementations are not clearly outlined. Instead we have some operations that are integral to the Stack data structure, but how it is implemented is up to the developer.

  • push(item): 'push' the item to the top of the Stack
  • pop(): remove and return the item at the top of the Stack
  • peek(): return the value of the item at the top of the Stack without removing it

How to Implement Stacks with arrays:

  • Array: how the data is stored in the stack
  • Size: the number of items added to the stack
  • Top Index: the index of the most recently added item in the stack array or Size - 1
    • When getting the most recent item, simply return the value at size - 1
    • When adding an item, add it using the size variable as an index

What is a Queue?

As you might know, a queue is the British English word for a line of people. Thus, you can think of queues as a line of people. The person who will leave the queue next is the person at the front of the queue while the person who most recently gets into the line will be at the end of the queue. The first person in is the first person out (First In First Out: FIFO).

Algorithms like Breath First Search or when there are virtual 'lines' (i.e., a line for buying tickets) are when Queues shine the most.

How are Queue ADTs?

Once again, the way an queue is implemented is fulid. You can use arrays or Linked Lists to do so. Since the 'how' is unclear, Queues are an Abstract Data Structure. This page will explain a Linked List implementation of Queues.

What are the Queue Operations?

As always, Queues have operations for getting and adding items to the data structures. However, their names are clear indicators of the fact they are queue operations which follow the FIFO property.

  • enqueue(item): inserts the item at the end of the queue
  • dequeue(): removes and returns item at the front of the queue
  • peek(): returns the item at the front of the queue without removing it

How to Implement Queue with Linked Lists:

  • Linked List: how the data is stored in the queue
    • For faster implementation the LinkedList need sto keep track of the first (head) and last (tail) elements in the list
    • Enqueue will use the tail of the list while dequeue will use the head of the list

Pseudocode

Stacks

Stack {
  size ← 0
  arr ← new array[]
}

push(item) {
  if size == arr.length
    resize()

  arr[size] ← item
  size++
}

pop() {
  temp ← arr[size - 1]
  size--
  return temp
}

Queues

Queues {
  size ← 0
  list ← new LinkedList()
}

enqueue(item) {
  list.addBack(item)
  size++
}

dequeue() {
  temp ← list.head
  list.head ← temp.next
  return temp.value
}
