Learning: Stacks and Queues

Prerequisite Knowledge

This demonstration expects a reasonable understanding of Java classes and methods, and C structs and LinkedLists.

Why Stacks and Queues?

Stacks and queues are reletively similar in their implementation and how they operate. Because of their similarity, they are often taught togehter since understanding one can give insight into the other.

Abstract Data Type (ADT)

One of their similarities is that they are both Abstract Data Types (ADT). ADTs are a conceptual model which describes the behavior of the data type (in Java, it is class) without a concrete outline of the implementation. As such, these focus on the 'what' (what the data type does) rather than the 'how' (how the data type does these things).

Why aren't LinkedLists or ArrayLists ADTs? These things aren't ADTs because the underlying implementation details are clearly outlined. For ArrayLists, we know that an array must be used to store the data. For our LinkedList we know we must create a Node, with each Node linking to some other Node. Now the specifics can change and maybe different, but the important points are the same across the board.

What is a Stack?

You can think of a Stack like a stack of plates. With a stack of plates, you put the most recent plate on the top of the stack. Then, when you are trying to grab a new plate, you also take from the top of the stack of plates. This is the same with Stacks in computer science. The last item added to the stack is the first item out of the stack (Last In First Out: LIFO).

Stacks are helpful in more complex aglorithms (Kosaraju’s Algorithm) or when computing mathematical equations with Reverse Polish Notation. In general, stacks are helpful when the Last In First Out property is necessary.

How are Stacks ADTs?

There are many ways to implement a Stack. You can use Linked Lists, arrays, or some other data structure to implement a stack. Within this explaination, we will be showcasing implementation using arrays.

What are the Stack Operations?

Remember, Stacks are ADTs and thus specific implementations is not clearly outlined. Instead we have some operations that are integral to the Stack but how it is implemented is up to the developer.

  • push(item): 'push' the item to the top of the Stack
  • pop(): remove and return the item at the top of the Stack
  • isEmpty(): checks if Stack is empty (size equals 0) or not
  • size(): returns the number of items in the stack
  • peek(): return the value of the item at the top of the Stack without removing it

How to Implement Stacks with arrays:

  • Array: how the data is stored in the stack
  • Size: the number of items added to the stack
  • Top Index: the index of the most recently added item in the stack array
    • When getting the most recent item, simply return the value at this index
    • If using the pop() function, the index with decrease
    • When adding an item, increase this index and add increase the index

What is a Queue?

As you might know, a queue is the British English word for a line of people. Thus, you can think of queues are a line of people. The person who will leave the queue next is the person at the front of the queue while the person who most recently gets into the line will be at the end of the queue. The first person in is the first person out (First In First Out: FIFO).

Algorithms like Breath First Search or when there are virtual 'lines' (i.e., a line for buying tickets), Queues are the got to data structure.

How are Queue ADTs?

Once again, the way an queue is implemented is fuild. You can use arrays or LinkedLists to do so. Since the 'how' is uncearly, Queues are Abstract Data Structures. This page will explain a Linked List implementation.

What are the Queue Operations?

  • enqueue(item): inserts the item at the end of the queue
  • dequeue(): removes and returns item at the front of the queue
  • isEmpty(): checks whetehr the queue is empty or not
  • size(): returns the number of items in the queue
  • peek(): returns the item at the front of the queue without removing it

How to Implement Queue with Linked Lists:

  • Linked List: how the data is stored in the queue
    • For faster implementation the LinkedList need sto keep track of the first (head) and last (tail) elements in the list
    • Enqueue will use the tail of the list while dequeue will use the head of the list
  • Size: the number of elements in the Queue
